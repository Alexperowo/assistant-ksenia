# История изменений

Все заметные изменения пользовательского поведения, форматов данных, зависимостей и требований оборудования записываются здесь. Подробные замеры конкретного компьютера остаются в `docs/AUDIT.md`.

## Не выпущено — 28 августа 2026

- Added: выключенные `heavy_candidate` Laguna S 2.1 и `quality_candidate` Ornith Quality Q6_K закреплены точными source commit/size/SHA-256; функциональные роли не менялись.
- Benchmark: одинаковый семисценарный A/B сравнил Laguna S DFlash off/Q4/BF16, conFIGur8tor Ornith MTP off/n=1/n=2/n=4, Qwen MTP off/n=2 и Ornith Quality. Qwen n=2 сохранил 72,12% acceptance и небольшой выигрыш; Laguna S DFlash и conFIGur8tor MTP замедлили ответы, поэтому кандидаты по умолчанию запускаются без speculative acceleration.
- Security: локальный SC117-подобный Ornith помещён в карантин конфигурации: структура и размер выглядят корректно, но SHA-256 не совпал с опубликованным SC117. Имя файла не принято за доказательство происхождения; незавершённый `.download` не трогали.
- Changed: candidate benchmark умеет атомарно писать отчёт, измерять load time, собирать request-level speculative counters и явно выбирать `draft-mtp`/`draft-dflash` только для одного in-memory прогона.
- Added: лёгкий Performance / Acceptance Harness расширяет прежний безопасный JSONL сквозными `trace_id/turn_id/task_id/request_id`, monotonic timestamps и voice→STT→LLM→TTS/cancellation milestones без отдельной telemetry-службы.
- Fixed: отмена streaming `llama.cpp` теперь сначала делает shutdown loopback-сокета и не блокирует разговор на синхронном `HTTPResponse.close()`; active/cancelled/stuck reader counters и shutdown latency остаются наблюдаемыми до фактической уборки.
- Added: каждый вызов инструмента получает собственный `tool_execution_id` и наблюдаемый lifecycle `PLANNED/APPROVED/STARTED/COMPLETED/FAILED/CANCELLED`; повтор после явного подтверждения отмечается отдельным attempt.
- Fixed: task checkpoint передаётся в executor; линейный поиск workspace, RAG-индексация и перебор векторов прекращаются в безопасных точках. Уже завершённые изменения не объявляются откатившимися.
- Fixed: при нескольких аудиовходах и отсутствующем Windows default Ксения больше не открывает произвольный endpoint; `audio-devices` явно просит выбрать `voice.wake_device`, а один-единственный вход остаётся автоматическим.
- Added: `voice-agent` использует один физический `AudioCaptureService`; wake/STT/stop получают точные 10-мс mono/int16 frames через аутентифицированный loopback и bounded drop-oldest queues. Эфемерный ключ не попадает в argv, repr и журнал; при отказе сохраняется прежний последовательный fallback.
- Verified: настоящий desktop START создал общий capture worker, faster-whisper CUDA и wake subscriber на одном порту; настоящий STOP удалил state и весь дочерний процессный граф. Физический JBL input всё ещё даёт почти цифровой ноль, поэтому пороги не занижались.
- Audited: SoundPlayer всё ещё не предоставляет far-end PCM. Изолированный `pywebrtc-audio` 0.1.0 прошёл 129 upstream-тестов и локальный AEC benchmark, но не добавлен в production до общего render reference и физического A/B.
- Audited: production sandbox оставлен fail-closed после проверки реальной машины: AMD-V/SVM выключен, WSL/container runtime отсутствуют; Job Object не выдаётся за filesystem/network boundary, а experimental Windows API и MXC не включены в обычный запуск. Контракт приёмки закреплён в `docs/SANDBOX-AUDIT.md`.
- Benchmark: Laguna/PoolSide/DFlash и Qwen/official/MTP прошли 16K/32K/48K/96K sweep. Меньший context экономит 1,8–2,9 ГБ VRAM, но не улучшает TTFT; reload 7–11 секунд уничтожает значительно более ценный тёплый prefix cache, поэтому рабочие 96K сохранены.
- Changed: chat transport явно передаёт `cache_prompt=true` и наблюдает только числовые cached tokens/hit ratio. `AgentSession` снимает tool schemas один раз на задачу; профиль не может неожиданно измениться внутри loop.
- Tests: добавлен живой cancellation-gate активной модели. На Laguna/PoolSide исходное воспроизведение заняло 2016 мс при отмене после 500 мс; после исправления три последовательных повтора завершили cancellation за 500–657 мс и вернули active/stuck readers к нулю.
- Added: `scripts/performance-report.py` читает активный и ротированные журналы, переживает повреждённые строки, показывает неполные traces и считает `count/min/average/p50/p95/max`; служебное «Слушаю» и ранние статусы не подменяют TTFA ответа.
- Changed: LLM transport фиксирует первый generated fragment, завершение и реальную cooperative cancellation; STT/TTS reader threads восстанавливают correlation только для своего `request_id`; agent/RAG/tool/model/research durations входят в общую измеряемую шкалу.
- Privacy: identifiers не содержат пользовательского текста, а prompt/transcript/answer/query/commands и credentials остаются под прежней redaction policy. Старый JSONL читается без миграции.
- Changed: официальный `llama.cpp` обновлён до stable v0.3.0 / b10621, commit `c1d0e7a00`, CUDA 12.4; новый формат `--version` поддерживается без ослабления проверки старых выпусков.
- Added: модели декларативно выбирают LLM backend. Laguna+DFlash использует закреплённый PoolSide commit `06f8ceb`, Qwen/Ornith — официальный b10621; в исполняемом коде нет условий по названию модели.
- Added: PoolSide patch provenance, build metadata и SHA-256 девяти runtime-файлов; локальная сборка устанавливается стадийно с резервной копией и автоматическим возвратом при ошибке.
- Fixed: PoolSide не получает отсутствующие в нём `--cors-origins/--no-cors-credentials`, но loopback и локальный API-key остаются обязательными.
- Verified: штатный `ModelManager` запустил и остановил Laguna+DFlash и Qwen+MTP+mmproj при фактическом контексте 98304; оба backend-а ответили по-русски и подтвердили speculative decoding в журнале.
- Security: `pip`, `setuptools` и CUDA Torch обновлены до проверенных `26.2.1`, `84.0.0` и `2.13.0+cu126`; закрыты GHSA-h35f-9h28-mq5c, GHSA-rrmf-rvhw-rf47 и все найденные OSV-совпадения старого pip. CUDA index и путь Torch lock перенесены в машинно проверяемую конфигурацию вместо варианта, зашитого в PowerShell.
- Fixed: все 14 ярлыков Ксении закреплены единым контрактом; CMD-обёртки возвращают реальный exit code, установщик очищает устаревшие hotkeys и перепроверяет target/working directory после сохранения `.lnk`.
- Docs: добавлен датированный документ передачи с честным статусом Live/AEC, фактическими ярлыками, новым локальным модельным инвентарём, отсутствующими reasoning-артефактами и безопасным порядком продолжения.

- Security: перед первым запуском каждого GGUF проверяются размер и полный SHA-256; результат кэшируется только для неизменившегося file identity/stat, а любое изменение заставляет пересчитать хэш. Символические ссылки моделей отклоняются до разрешения пути.
- Security: активное управление браузером и Windows по умолчанию скрыто и отключено; строковые значения вроде `"false"` больше не считаются истинными. Windows-ввод останавливается fail-closed, если активное или целевое окно нельзя точно определить.
- Fixed: чтение потока `llama.cpp`, включая tool-call и tokenizer-запрос, стало отменяемым во время сетевого зависания; checkpoint проверяется примерно каждые 100 мс, а фрагменты tool-call собираются обратно до исполнения.

Остановка больше не может проиграть гонку запуску аудиопроцесса или допустить новую фразу после stop.
- Fixed: фоновый listener команды «стоп» и голосовое подтверждение передают единственный микрофон через явный gate, не открывая два audio worker одновременно.
- Fixed: конфигурация, PID/state, API-ключ, LAN PIN, модельный integrity-cache, журнал отмены и файловые изменения используют уникальную атомарную запись и межпроцессную блокировку; операции изменения и их undo-record составляют одну сериализованную транзакцию.

- Added: отдельный Live v1-контур (`LiveSession`, `StreamingTTS`, `BargeInController`, `ConversationCoordinator`) получает безопасные дельты итогового ответа, подтверждает окончание каждой TTS-фразы и отменяет генерацию до остановки аудио. - Changed: RAG получил порог чисто смыслового совпадения, стабильную сортировку равных кандидатов и явный результат `no_match` вместо случайного фрагмента.
- Security: одна задача по умолчанию задаёт не более четырёх вопросов подтверждения; жёсткий программный потолок — восемь.
- Security: исторический промежуточный pin `setuptools 78.1.1` закрыл GHSA-5rjg-fvgr-3xxf до появления совместимого обновления полного CUDA-контура.

## 0.1.0 — 11 августа 2026

- Создан локальный голосовой дворецкий-разработчик для Windows 11 и слабовидящего пользователя.
- Реализованы четыре роли, одна активная GGUF-модель, 64K, MTP, reasoning budget и управляемая длина ответа.
- Добавлены Vosk wake/stop, faster-whisper, Silero Xenia, Bluetooth-защита начала речи и медиакнопка.
- Добавлены долговечные задачи, сжатая история, подтверждённые факты, межролевая память и гибридный RAG.
- Добавлены web research, Chromium isolation, Windows Automation, подтверждения, журнал изменений и LAN-панель.
- Проведён аудит безопасности, журналов и доступности; создано 191 автоматическое испытание и живые gates.
- Добавлены `AGENTS.md`, полный комплект документации передачи, lock-файлы Python, аппаратные профили и машинный release manifest.
- Добавлены безопасные `INSTALL.cmd`, `UPDATE.cmd`, `ROLLBACK-UPDATE.cmd`, сборка и проверка чистого ZIP без моделей/личных данных.
- Настройки по умолчанию очищены от абсолютных путей конкретного компьютера; реальные пути Александра остаются только в исключённом из архива `config/user.json`.
- Подготовлено публичное оформление сырой alpha-версии: эмблема в README, MIT, GitHub Actions, issue/PR templates, CONTRIBUTING и политика приватного сообщения об уязвимостях.

## Правила будущих записей

- `Added`, `Changed`, `Fixed`, `Security`, `Migration`, `Removed` описываются отдельно.
- Указывается, требуется ли действие Александра.
- Изменение схемы данных получает инструкцию резервного копирования и отката.
- Обновление модели содержит benchmark, а обновление движка — release/commit и compatibility gate.
