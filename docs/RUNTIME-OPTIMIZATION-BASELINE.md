# Runtime context, prompt cache и ToolProfiles: baseline

Дата измерения: 30 августа 2026 года. Это решение основано на реальных запусках двух рабочих backend-ов, а не на оценке по размеру KV.

## Методика

Скрипт `scripts/runtime_context_benchmark.py` для каждого размера контекста:

1. создаёт копию настроек только в памяти;
2. не меняет `config/default.json` или `config/user.json`;
3. запускает штатный `ModelManager` и проверяет фактический `n_ctx`;
4. отправляет первую и следующую реплику одной сессии с одинаковым system prefix и полными текущими tool schemas;
5. явно устанавливает `cache_prompt=true`;
6. собирает load time, TTFT, prompt/completion/cached tokens, process private bytes и общий VRAM snapshot;
7. после каждого режима останавливает сервер, а в конце восстанавливает исходную модель либо оставляет порт свободным, если исходно модели не было.

Контексты: 16 384, 32 768, 49 152 и 98 304. В каждой точке сделан один cold запуск и одна связанная пара коротких запросов. Поэтому результаты надёжно показывают порядок величин и зависимость от контекста, но не являются p50/p95: перед тонкой настройкой нужны повторения с перемешанным порядком.

Полный текущий профиль содержит 20 tools, 8 219 байт канонического JSON. Hash схемы одинаков во всех запусках. Реальные JSON-отчёты находятся в локальном `runtime/benchmarks` и намеренно не входят в Git.

## Подтверждённый bottleneck

Главная задержка первого agent turn — cold prompt evaluation полного system/tool prefix, а не резервирование большого KV:

- Laguna: около 62–64 секунд на 2 215 prompt tokens;
- Qwen: около 23 секунд на 2 027 prompt tokens;
- следующий ход той же сессии переиспользует почти весь prefix и падает до 1,1–1,8 секунды.

Prompt cache у обоих закреплённых backend-ов фактически работает. `--parallel 1` удерживает одну slot, а `--cache-prompt` включён сервером по умолчанию. Production transport теперь дополнительно передаёт `cache_prompt=true`, чтобы не зависеть от будущего изменения default, и пишет только числовые `cached_prompt_tokens`/`prompt_cache_hit_ratio`.

`--cache-reuse N` не включён. Это отдельная оптимизация KV shifting, а не условие обычного prefix reuse. Её значение нельзя выбирать без A/B, проверки качества и текущих upstream-регрессий prompt cache.

## RuntimeProfile: решение

Автоматическое переключение LIVE 16K ↔ LONG 96K сейчас **не внедряется**.

Причины:

- изменение `context_size` меняет launch signature и требует полного restart;
- reload занимает 7–11 секунд;
- restart уничтожает тёплый KV prefix, цена которого на Laguna достигает примерно минуты;
- 96K уже помещается и сохраняет максимальную long-context способность;
- измеримый плюс 16K — освобождённая память, а не меньший TTFT.

Отдельный 16K Live runtime имеет смысл только если появится постоянно живой второй backend/slot либо давление VRAM станет реальным bottleneck. Тогда нужны hysteresis, минимальное время удержания профиля, checkpoint/summary перехода и A/B 20–30 ходов. До этого текущие 96K остаются честно лучшим эксплуатационным компромиссом.

## Stable ToolProfiles: решение

Фактические маршруты уже образуют стабильные профили:

- `CHAT` — tools отсутствуют;
- `RESEARCH_INTERNAL` — специализированный coordinator, tools в LLM prompt отсутствуют;
- `PLANNING_READ_ONLY` — один заранее собранный read-only набор;
- `AGENT_FULL` — полный разрешённый набор executor-а.

Исправлена одна реальная нестабильность: `AgentSession` раньше заново вызывал `tool_schemas()` на каждом шаге loop. Теперь `AGENT_FULL` снимается один раз до первого model step и тот же объект используется до конца задачи. Диагностика записывает профиль, count, bytes и SHA-256 схемы без аргументов пользователя.

Более узкие `DEVELOPER/WINDOWS/MESSAGING` пока не добавлены. Текущий router не классифицирует эти подтипы с доказанной точностью, а ошибочно узкий профиль способен убрать нужный инструмент на всю задачу. Сначала нужен corpus реальных маршрутов и измерение ошибочного выбора; при неуверенности профиль обязан расширяться до `AGENT_FULL` до начала loop, а не в его середине.

## Повторение

```powershell
python scripts\runtime_context_benchmark.py --profile generalist
python scripts\runtime_context_benchmark.py --profile reasoning
```

Перед повтором убедиться, что Ксения не выполняет задачу. Скрипт управляет активной моделью и её портом, но не меняет файлы конфигурации. После аварийного прерывания проверить `runtime/state.json`, PID/executable и порт штатным Doctor, не завершая неизвестный процесс.
