# Чистая установка и восстановление

## Два разных сценария

- `INSTALL.cmd` — чистая Windows или восстановление отсутствующей среды.
- `UPDATE.cmd` — уже установленная Ксения и переход к версиям, закреплённым текущим релизом.

На рабочем компьютере Александра без причины повторно запускать установку не нужно. И `INSTALL`, и `UPDATE` сохраняют `config/user.json`, `runtime`, `workspace` и модели.

## Что находится в переносимом архиве

Online-архив содержит код, документы, конфигурацию по умолчанию, lock-файлы, процедуры, интерфейс и установочные скрипты. Он намеренно не содержит:

- GGUF и другие веса LLM;
- Whisper, embedding и другие веса моделей;
- личный `config/user.json`;
- память, задачи, журналы и PIN из `runtime`;
- пользовательские проекты из `workspace`;
- виртуальную среду Python, локальный Chromium и распакованный `llama.cpp`;
- ключи, сертификаты и пароли.

Поэтому архив небольшой и не зависит от объёма VRAM. Во время online-установки нужные закреплённые компоненты скачиваются с официальных источников и проверяются. Большие LLM всегда устанавливаются отдельно.

## Требования

- Windows 11 x64; PowerShell 5.1 входит в систему.
- Доступ в интернет для online-установки.
- Права обычного пользователя; глобальная установка Python не требуется.
- Для проверенного CUDA-контура — современная NVIDIA с рабочим драйвером.
- Не менее 8 ГБ ОЗУ для компактного режима; фактическая модель может требовать значительно больше.
- Свободное место: несколько гигабайт для Python/CUDA-библиотек, Chromium и голосового пакета плюс отдельное место под модели.

AMD/Intel GPU и полностью CPU-режим архитектурно возможны в `llama.cpp`, но текущий lock-файл содержит проверенную NVIDIA CUDA-сборку. Новый backend нельзя включать только переименованием архива: нужен отдельный lock, тесты и документация.

## Пошагово на чистой Windows

1. Распаковать архив в постоянную папку, например `D:\AI\Ksenia`. Не запускать из ZIP.
2. Открыть `HARDWARE-REPORT.cmd`. Скрипт ничего не меняет и подсказывает стартовый профиль.
3. Запустить `INSTALL.cmd`.
4. Дождаться установки отдельного Python 3.12, точных библиотек, Chromium, Vosk, Whisper и закреплённого `llama.cpp`.
5. Установщик проверит подпись Python, SHA-256 известных архивов/моделей и выполнит аудит.
6. Положить выбранные GGUF в отдельную папку моделей. Не хранить их внутри проекта.
7. Указать реальные пути в `config/user.json` или через меню Ксении.
8. Снова открыть `AUDIT.cmd`.
9. Выполнить пользовательскую приёмку по `docs/ИНСТРУКЦИЯ-АЛЕКСАНДРА.txt`.

Если программы и модели должны лежать в заранее выбранных местах, установщик принимает явные параметры:

```powershell
INSTALL.cmd -InstallRoot "E:\KseniaRuntime" -ModelStorageRoot "F:\AI\Models"
```

`InstallRoot` хранит отдельный Python, загрузки, Chromium и профиль браузера. `ModelStorageRoot` хранит внешние веса речи и выбранные GGUF; LLM всё равно не скачивается автоматически. Без параметров установщик выбирает доступный диск консервативно и записывает фактические пути только в личный `config/user.json`.

Если основная LLM ещё не установлена, Doctor честно покажет её как отсутствующую. Это не означает, что Python или голосовые компоненты установились неправильно.

## Что делает INSTALL

1. Читает `runtime-assets.lock.json` и lock-файлы `requirements`.
2. Использует подходящий существующий Python 3.12 или проверяет цифровую подпись официального установщика.
3. Создаёт отдельную виртуальную среду, не меняя системный PATH.
4. Устанавливает точные версии pip, CUDA Torch и остальных Python-пакетов.
5. Стадийно устанавливает `llama.cpp` из архивов с SHA-256.
6. Устанавливает отдельный Chromium Playwright.
7. Загружает закреплённые Vosk и Whisper, если они не найдены и не указан режим пропуска весов.
8. Создаёт только недостающие личные настройки и ярлыки.
9. Запускает полный аудит.

Повторный запуск является восстановлением до версий lock-файлов, а не обновлением до случайного `latest`.

## Разное оборудование

`HARDWARE-REPORT.cmd` измеряет Windows, процессор, ОЗУ, NVIDIA и VRAM и выбирает консервативный старт из `hardware-profiles.json`. Профиль не выбирает модель автоматически и не обещает, что любой GGUF поместится.

При замене компьютера отдельно учитываются:

- размер и архитектура weights;
- KV-кэш для фактического контекста;
- MTP/draft context;
- CUDA graphs и рабочие буферы;
- offload в ОЗУ и файл подкачки;
- реальная скорость prefill и генерации.

После установки новой модели обязателен локальный benchmark. Настройки Александра с 16 ГБ VRAM и 64K нельзя слепо переносить на 8 ГБ.

## Модели как отдельные пакеты

Для каждой модели нужно хранить вне дистрибутива:

- источник и точное имя репозитория;
- имя GGUF;
- размер в байтах и SHA-256;
- роль и аргументы запуска;
- русский A/B benchmark;
- требования VRAM/ОЗУ и известные ограничения.

Модель считается рабочей только после добавления в `config/user.json`, проверки целостности и живого допуска. Установщик никогда не ищет «похожий» файл и не скачивает многогигабайтную LLM по одному имени роли.

## Перенос существующих данных

Перед переносом сохраните отдельно:

- `config/user.json`;
- `runtime/memory`, `runtime/tasks` и при необходимости безопасные журналы;
- `workspace`;
- внешнюю папку моделей;
- профиль браузера, только если нужны существующие входы на сайты.

Сначала разверните чистый архив и выполните INSTALL, затем верните данные в соответствующие места. Не копируйте старую виртуальную среду Python между разными Windows.
