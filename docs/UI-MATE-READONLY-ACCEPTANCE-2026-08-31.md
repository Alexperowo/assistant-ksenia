# UI-Mate: read-only corpus и первый acceptance baseline

Дата: 31 августа 2026 года.

## Цель

До подключения UI-Mate к реальному вводу Windows нужно измерять не «похожесть ответа», а корректность следующего предложенного шага на неизменяемом снимке экрана. Runner читает заранее размеченные изображения, получает одно строго типизированное предложение UI-Mate, при необходимости передаёт его независимому reviewer Agents-A1 и **ничего не нажимает**.

Production-контур состоит из:

- `src/butler/ui_evaluation.py` — строгий manifest, безопасное разрешение путей и проверка результата;
- `scripts/evaluate_ui_mate_readonly.py` — запуск corpus, управление только теми resident-моделями, которые он сам поднял, и JSON-отчёт;
- `tests/test_ui_evaluation.py` — traversal, неизвестные action/поля, ограничения coordinate/keys, альтернативные штатные действия и отсутствие зависимости от Windows executor.

## Контракт manifest

Manifest имеет `version=1` и от 1 до 50 случаев. Путь снимка относителен каталогу manifest, после `resolve()` обязан оставаться внутри него, а размер изображения ограничен 25 МБ. Неизвестные поля и неизвестные UI actions отвергаются.

Текущий gate принимает в expectations только действия, которые можно проверить без двусмысленности: клики/перемещение с обязательной coordinate region и клавиатурные actions с обязательным точным списком keys. `type`, `scroll`, `wait`, `call_user` и `finished` разрешены самим UI-Mate, но пока не могут быть положительным эталоном corpus: принимать их только по имени было бы ложной строгостью. Для них сначала нужен отдельный точный контракт текста, направления/величины или статуса.

Один правильный следующий шаг может иметь несколько эквивалентных вариантов. Например, закладку Chromium допустимо создать горячей клавишей или нажатием видимой звезды:

```json
{
  "id": "chromium-bookmark-page",
  "task": "Bookmark the current page in Chromium.",
  "screenshot": "chrome_bookmark_page.png",
  "expectations": [
    {"action": "hotkey", "keys": ["ctrl", "d"]},
    {"action": "left_click", "coordinate_region": [930, 100, 955, 140]}
  ],
  "forbidden_actions": ["type", "finished"]
}
```

Такой контракт не подгоняет модель под единственный эталонный жест, но и не принимает произвольный семантически похожий ответ.

## Первый живой corpus

Seed corpus содержит три заранее сохранённых снимка 1920×1080:

1. VS Code: открыть Extensions для установки autoDocstring.
2. Chromium: добавить текущую страницу в закладки.
3. Ubuntu: начать установку Spotify через Ubuntu Software, не через терминал.

Команда:

```powershell
python scripts/evaluate_ui_mate_readonly.py "<corpus>\manifest.json" --review --start-models
```

Первый прогон формально показал 2/3: Chromium выбрал штатную звезду `[942, 120]`, тогда как первоначальная разметка разрешала только `Ctrl+D`. Reviewer действие одобрил. Это была подтверждённая ошибка измерителя, а не модели. Схема была исправлена на несколько независимых expectations и покрыта регрессиями.

Повторный неизменный прогон:

| Случай | Предложение | Reviewer | Время |
|---|---|---:|---:|
| VS Code Extensions | `left_click [48, 280]` | approve | 10 484 мс |
| Chromium bookmark | `left_click [943, 120]` | approve | 9 797 мс |
| Ubuntu Software | `left_click [19, 619]` | approve | 9 891 мс |

Итог окончательного прогона со строгим action-specific контрактом: `3/3`, общее время с холодным запуском/остановкой моделей — `40 344 мс`, revisions — `0`, `executed_actions=0`. После прогона порты resident-сервисов освобождены.

После добавления runner полный проектный `check.ps1` прошёл 403/403 теста, три перемешанных порядка, release/dependency/Doctor/LAN и голосовой round-trip. LLM/RAG в этом общем gate явно пропущены по текущему неактивному состоянию; сам corpus выше является отдельной живой проверкой resident-моделей.

## Границы доказанного

Этот результат подтверждает protocol, загрузку снимков, первый шаг трёх сценариев, независимый policy review и отсутствие исполнения. Он **не** означает готовность автономного управления:

- три случая не заменяют требуемые 20–30;
- проверен один масштаб сохранённых снимков;
- multi-monitor mapping покрыт unit-тестами, но не corpus разных физических раскладок;
- reviewer не получает изображение и проверяет политику/смысл предложения, а не пиксельную точность;
- не проверена последовательность нескольких действий и достижение конечного результата;
- реальный Windows executor намеренно не импортируется runner-ом.

## Следующий gate

1. Расширить corpus до 20–30 read-only шагов: Windows 11, Chromium, проводник, настройки, VS Code, диалоги, отрицательные координаты второго монитора и 100/150/200% DPI.
2. Для каждого случая заранее описать все действительно допустимые первые шаги; расхождения измерителя исправлять отдельно от модели.
3. Считать accuracy, unsafe proposal rate, reviewer false-approve/false-reject, revisions и p50/p95.
4. Только после зелёного corpus провести одно обратимое действие с явным подтверждением Александра через существующий `windows_*` tool → Permission Broker → executor.
5. Любая регрессия возвращает контур в read-only; прямой путь UI-Mate → Windows input не допускается.
