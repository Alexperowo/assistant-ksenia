# Аудит проекта

Дата: 12 августа 2026 года.

## Итог

Программный фундамент Ксении готов к поэтапной пользовательской приёмке. Автоматически проверены код, конфигурация, модели, голос без микрофона, память, RAG, браузер, LAN, разрешения, отмена и журналы. Живой исследовательский запрос на официальную страницу прошёл полностью.

- `HARDWARE-REPORT.cmd` получает объём NVIDIA VRAM через `nvidia-smi`, а не через ограниченное 32-битное поле WMI. На этом компьютере он корректно увидел 16 311 МБ VRAM, 15,9 ГБ ОЗУ и предложил консервативный профиль 64K с KV `Q8_0/Q5_0`.
- Полный цикл обслуживания `llama.cpp` испытан в изолированной копии: два настоящих официальных архива проверены по SHA-256, движок установлен через staging, заменён с резервной копией и восстановлен штатным скриптом отката.

- `UPDATE.cmd -CheckOnly` на рабочей установке подтвердил одобренные версии без остановки модели и без каких-либо изменений.
- Сборщик проверяет разрешённый состав, запрещает веса моделей, ключи и личные данные, создаёт хеш каждого файла, затем распаковывает готовый ZIP и валидирует его повторно.

## Существенные дефекты, найденные и исправленные

1. Обычный поиск Bing RSS мог игнорировать точный технический запрос. Основным стал DuckDuckGo HTML, Bing оставлен резервом.
2. Headless Chromium получал антибот-проверку DuckDuckGo. Поисковая выдача теперь скачивается отдельным ограниченным адаптером, а найденные страницы по-прежнему читает Chromium.
3. Редирект поисковика мог теоретически уйти на посторонний адрес до последующей проверки. Теперь переход блокируется до соединения и разрешён только между фиксированными HTTPS-доменами провайдеров.
4. Qwopus вернул Jinja 500, когда данные исследования шли вторым системным сообщением. Все системные инструкции централизованно объединяются в один первый блок; это также защищает сжатие памяти, предел инструментов и планировщик.
5. Сжатая память могла не попасть в короткий бытовой диалог. Теперь она включается в его системный контекст с лимитом 6000 символов.
6. Официальный запрос открывал шесть почти одинаковых страниц и занял 74 секунды. Для точной официальной страницы лимит снижен до трёх; повторный тест занял 31 секунду. Товарные цены по-прежнему используют полный набор продавцов.
7. Повторные ошибки Bluetooth-микрофона ранее могли озвучиваться без остановки. Добавлены ограниченный backoff, редкие напоминания и сообщение о восстановлении.
8. Процесс модели мог считаться остановленным до фактического закрытия дескрипторов. Завершение теперь ждёт подтверждённого выхода и освобождения порта.
9. Общие инструменты клавиатуры и мыши могли обойти специализированный запрет оплаты. Добавлена проверка финансового контекста активного окна, селектора и аргументов.
10. Чтение локальных данных с последующим веб-запросом могло стать каналом утечки через prompt injection. Теперь такой переход требует отдельного подтверждения.
11. В переносимом `default.json` оставались абсолютные пути `D:/G:` исходного компьютера. Они перенесены только в личный `user.json`; release validator теперь отклоняет любую новую машинную привязку в настройках по умолчанию.
12. Первый clean-package smoke-test выявил warning Playwright и ненадёжный рекурсивный поиск `chrome.exe` в глубоком дереве Windows. Установщик теперь не запускает лишнее API-соединение, скачивает Chromium без ненужного Headless Shell и проверяет точный путь без рекурсивного обхода.
13. Личный `user.json` мог ослабить обязательное подтверждение или финансовый запрет, отдельный запуск проектных тестов оставался без согласия, а внешний `allowed_roots` — расширить файловую область. Теперь код считает тесты исполнением кода, применяет неослабляемый минимум после настроек и принимает корни только внутри `developer.workspace_dir`.
14. Параллельный поиск и чтение страниц добавляли результаты по скорости ответа сети, поэтому одинаковая задача могла получить иной порядок доказательств. Параллельность сохранена, но сбор теперь детерминирован по запросам и выбранным источникам.
15. Векторный RAG всегда выдавал ближайший фрагмент даже при слабой связи. Добавлены порог 0,30 для чисто смысловых кандидатов, стабильные tie-break, диагностическая similarity и честный `no_match`; точное лексическое совпадение не теряется.
16. Ошибочная модель могла утомлять пользователя последовательными вопросами разрешения. По умолчанию допускаются четыре самостоятельных запроса на задачу, жёсткий потолок — восемь; затем остальные рискованные действия отменяются.
17. GitHub после публикации обнаружил у закреплённого `setuptools 78.1.0` высокий path traversal и средний дефект Unicode-исключений sdist. Высокий дефект закрыт точечным обновлением до 78.1.1. Исправляющая оба версия 83.0.0 конфликтует с Torch 2.11 (`setuptools<82`), поэтому после проверки была отвергнута; средний advisory относится к созданию sdist на macOS APFS/HFS, тогда как проект поддерживает Windows и собирает собственный ZIP с машинным manifest.

## Гарантии безопасности

- LLM и эмбеддер доступны только на loopback и требуют локальную авторизацию.
- Порт с неизвестным владельцем не завершается и не принимается за модель Ксении.
- Неполный GGUF отбрасывается до создания процесса.
- `file://`, `localhost`, приватные IP, `.local`, URL с учётными данными и непубличные редиректы запрещены.
- `.env`, credentials, private key, PEM/KEY/PFX/P12, KDBX и похожие файлы не читаются, не ищутся и не индексируются.
- Содержимое файлов, вводимый текст, запросы, аргументы команд, PIN и секретные параметры URL скрываются из диагностики.
- Файловые операции ограничены `workspace`, запись и удаление подтверждаются, отмена проверяет последующую ручную правку.
- PowerShell, `cmd`, inline-код и опасные Git-команды агенту не выдаются.
- Финансовые действия запрещены. Отправка сообщения подтверждается отдельно каждый раз.
- Личная конфигурация не может опустить встроенный уровень защиты или вывести разрешённый файловый корень за пределы workspace.
- Слабое чисто смысловое совпадение RAG не передаётся модели как доказательство.

## Известные границы и технический долг

- Бесплатные поисковики и магазины могут показать CAPTCHA, 429 или неполную цену. Ксения должна сообщить это, а не додумывать.
- LAN работает по HTTP внутри домашней сети, не предназначен для интернета.
- Визуальной модели пока нет; окна без UI Automation управляются координатами только после подтверждения.
- Семантика безымянного пикселя неизвестна, поэтому координатный клик нельзя считать полностью защищённым одной классификацией окна.
- После аварии задача восстанавливает запрос и состояние, но не середину токена.
- 26B/64K плотно использует VRAM, ОЗУ и файл подкачки; качество выбрано важнее скорости.
- RAG-векторы сейчас перебираются линейно; для огромных репозиториев нужен ANN.
- Текущий переносимый ZIP является online bootstrap: он не содержит моделей, Python wheelhouse, Chromium и CUDA-библиотеки. Полная офлайн-установка без интернета ещё не заявлена как готовая.
- JSON сохраняется через временный файл и `replace`, но без явного `fsync`; при внезапном отключении питания остаётся малая системная вероятность потери последней записи.
- Крупные функции в `cli.py`, `agent.py`, `orchestrator.py` и `tools.py` покрыты тестами, но после приёмки требуют постепенного разбиения на меньшие модули.
- Dependabot всё ещё показывает средний GHSA-h35f-9h28-mq5c для `setuptools<83`. Его уязвимый сценарий — сборка sdist на macOS APFS/HFS с Unicode-коллизией; Ксения поддерживает Windows 11 и создаёт ZIP через собственный разрешительный manifest, без `MANIFEST.in` и sdist. Alert не скрывается и будет закрыт после снятия ограничения Torch `setuptools<82`.
- Dependabot всё ещё показывает низкий GHSA-rrmf-rvhw-rf47 для `torch.jit.script` в Torch до 2.13. Проект не вызывает `torch.jit.script` (Silero использует только `torch.jit.load` доверенного закреплённого веса), а официальный индекс CUDA 12.8 пока предлагает максимум проверенный 2.11.0. Переход на другой CUDA/Torch стек без голосового A/B был бы опаснее; alert остаётся открытым и должен быть пересмотрен при появлении официальной совместимой сборки 2.13+.
- Приблизительный строковый охват быстрого слоя равен 40,6%; это честная нижняя метрика, а не заявление о 90% code coverage. Живые интеграции и ручная приёмка считаются отдельно.
- Чистый установщик не загружает основную LLM автоматически.

Подробный разбор качества самих тестов: [TEST-AUDIT.md](TEST-AUDIT.md).
