# Передача работы над LLM backend-ами — 29 августа 2026

Этот checkpoint дополняет исторический `TRANSFER-2026-08-28.md` и имеет приоритет в вопросах моделей и `llama.cpp`.

## Итог

Ксения больше не пытается запускать все GGUF одним глобальным executable. Профиль модели декларативно выбирает backend, а код не определяет семейство по имени файла:

- `generalist` → `poolside` → `tools/llama.poolside/llama-server.exe`;
- `reasoning` и выключенный `candidate` → `official` → `tools/llama.cpp/llama-server.exe`;
- embeddings продолжают использовать закреплённый официальный runtime.

Loopback, локальный API-key, один активный большой процесс, проверка PID/executable и запрет завершения неизвестного владельца порта одинаковы для обоих backend-ов. Только поддержка отдельных CLI flags, сейчас `cors_controls`, берётся из типизированной декларации backend-а.

## Обслуживание

`scripts/maintenance.py status` проверяет оба backend-а. Для PoolSide проверяются version output, путь, patch и все runtime hashes. `scripts/install-local-backend.ps1` принимает явный каталог проверенной сборки, разворачивает его в staging, сохраняет предыдущую версию и возвращает её при ошибке. Скрипт намеренно не скачивает ветку и не компилирует fork во время обычного пользовательского обновления.

`UPDATE.cmd` автоматически обновляет официальный архивный backend. Если PoolSide не совпадает с lock, update останавливается и просит предоставить проверенный `SourceDirectory`, вместо случайной сборки из `latest`.

Active-model cancellation-gate воспроизвёл прежние 2016 мс и после исправления дал 500–657 мс на трёх повторах с нулевыми active/stuck HTTP readers после cleanup.
