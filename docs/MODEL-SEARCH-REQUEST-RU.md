# Сообщение для следующего поиска моделей

Используйте этот текст только когда текущий русский benchmark покажет измеримую проблему. Новая model card сама по себе не является причиной менять рабочий профиль.

---

Проведи актуальный на дату выполнения поиск по Hugging Face, GitHub и официальной документации `llama.cpp`. Не придумывай репозитории, файлы, MTP/DFlash/APEX, размеры или результаты. Каждое техническое утверждение должно иметь прямую ссылку на первичный источник, точный commit и воспроизводимую команду.

Целевая система:

- Windows 11 x64;
- NVIDIA RTX 2080 Ti с 22 ГБ VRAM и 48 ГБ ОЗУ;
- закреплённый официальный `llama.cpp b10621` (stable v0.3.0), CUDA 12.4, для Qwen/Ornith; закреплённый PoolSide commit `06f8ceb` для Laguna/DFlash; новый runtime рассматривается отдельно и не устанавливается ради модели без полного engine gate;
- одновременно работает одна крупная LLM;
- целевой контекст рабочих профилей 96K, KV `K=Q8_0`, `V=Q4_0`;
- обязательны русский язык, Jinja chat template, tool/function calling, код, исследование и восстановление после ошибочного tool result;
- качество важнее рекорда скорости, но prefill, tok/s, VRAM и ОЗУ должны быть измерены.

Текущие профили для сравнения:

- `generalist`: Laguna XS 2.1 APEX I-Quality + отдельный DFlash на PoolSide backend;
- `reasoning`: Qwen 3.8 27B Opus Distill v2 + MTP + multimodal projector на официальном backend;
- `candidate`: выключенный conFIGur8tor Ornith 1.5 35B-A3B APEX MTP Fixed, точный артефакт закреплён, но собственный 16K MTP on/off gate ещё не выполнялся; старый A/B SC117 к нему не относится.

Для каждого кандидата укажи:

1. Точное имя репозитория, файл GGUF и прямые ссылки.
2. Полный commit, дату содержательного обновления, лицензию и базовую модель.
3. Dense/MoE, общие и активные параметры, квант, размер и effective BPW.
4. Chat template, reasoning format и поддержанный tool-call формат.
5. Для MTP/DFlash/DSpark: реальные тензоры или отдельный drafter, точную команду и минимальный commit `llama.cpp`.
6. Для vision: точный projector, его размер/квант и воспроизводимый image test.
7. Отдельный расчёт weights, KV 96K, speculative/projector, CUDA buffers, CPU offload и запаса памяти; пометь расчёт и реальный замер раздельно.
8. Проверяемые agent/tool/code/reasoning/long-context результаты и отдельно русский язык. Авторский self-eval не выдавай за независимый benchmark.
9. Известные runaway generation, rumination, chat-template, speculative-acceptance и совместимые quant/backend ограничения.
10. Какой текущий профиль кандидат должен превзойти и какой локальный тест это докажет.

Сразу отфильтруй:

- название MTP/DFlash/APEX без поддержанного файла, тензоров и команды;
- speculative weights только в Safetensors без рабочего пути для локального backend;
- плавающий revision, несуществующие ссылки, split без полного набора и неизвестный размер;
- вариант, который не оставляет измеримого запаса при 96K;
- модель без устойчивого русского function calling;
- замену ради более нового номера версии без выигрыша на реальных задачах Александра.

Результат:

1. Короткая таблица только прошедших фильтр кандидатов.
2. Отдельно лучший generalist, reasoning и экспериментальный профиль.
3. Для каждого финалиста — полный план локального A/B: семь базовых функций, tool schema, prompt injection, ошибка инструмента, длинная история, скорость, acceptance, VRAM/ОЗУ и освобождение порта.
4. Явный вывод «не менять текущую систему», если доказательств преимущества нет.
