# Конфигурация

## Слои

`config/default.json` входит в дистрибутив и содержит безопасные переносимые значения. `config/user.json` содержит только отличия конкретного компьютера. При загрузке словари глубоко объединяются: значение пользователя обычно переопределяет соответствующее значение по умолчанию, остальные поля сохраняются. Исключение — встроенный минимум безопасности: личная настройка не может заменить обязательное подтверждение на `allow`, разрешить финансовое действие или вывести файловый корень за `developer.workspace_dir`.

Следствия:

- обновление `default.json` не должно стирать личные пути;
- `user.json` не нужно копировать целиком из примера;
- неизвестное или устаревшее личное поле нужно мигрировать осознанно;
- `user.json` не включается в Git и релизный архив.

## Основные разделы

| Раздел | Назначение |
|---|---|
| `assistant` | имя, роль по умолчанию, голосовые статусы |
| `paths` | `llama-server`, модели и runtime |
| `server` | только loopback, порт и время запуска |
| `engine_backends` | переносимые executable и проверенные возможности LLM-runtime |
| `default_engine_backend` | fallback backend для профиля без явного назначения |
| `voice` | Python, Vosk, Whisper, устройство, паузы и тайм-ауты |
| `live` | opt-in потоковая озвучка, размер фраз и предел ожидания playback |
| `browser` | Chromium и постоянный профиль |
| `models` | конкретные GGUF-профили и аргументы `llama.cpp` |
| `model_services` | независимые loopback endpoint и state-файлы процессов моделей |
| `runtime_routing` | резидентная малая пара, research stage modes и декларативный UI review-контур |
| `capability_roles` | соответствие функций профилям моделей |
| `agent` | пределы шагов, инструментов, подтверждений и голосовых статусов |
| `generation`, `routing` | лимиты ответа, плана и исследования |
| `memory`, `rag` | сжатие, постоянная память и индекс |
| `permissions` | allow/confirm/deny для каждого класса действий |
| `developer` | рабочая область и разрешённые программы |
| `lan` | домашний интерфейс и порт панели |

## Роль и модель — не одно и то же

`assistant`, `researcher`, `developer`, `heavy_brain` — функциональные роли. `generalist`, `reasoning`, `candidate` — семантические идентификаторы профилей GGUF. Функция назначается только через `capability_roles`; исполняемый код не делает выводов из имени файла, семейства модели или размера параметров.

## Каталоги моделей без машинного хардкода

```json
{
  "paths": {
    "models_dir": "../models-primary",
    "model_search_dirs": ["../models-secondary"]
  }
}
```

Относительные значения разрешаются от корня проекта; в личном `user.json` допустим и абсолютный путь этого компьютера. Для каждого артефакта сначала проверяется точное имя во всех корнях, затем вложенные каталоги. Большой файл не копируется в проект. Настройка путей обновляет только раздел `paths` и атомарно сохраняет остальные личные параметры.

## Декларативный каталог профилей

Каждый профиль содержит ссылку `backend`, `artifacts.model` и при необходимости `artifacts.draft` или `artifacts.projector`. Backend обязан существовать в `engine_backends`; неизвестное имя даёт отказ при загрузке конфигурации. Каждый распространяемый артефакт закрепляет `source_repo`, полный 40-символьный `source_revision`, исходное имя, ожидаемый размер и SHA-256. Раздел `acceleration` объявляет только поддержанные движком значения `none`, `draft-mtp`, `draft-dflash` или `draft-dspark`; для DFlash/DSpark обязателен отдельный draft-артефакт. Число speculative tokens ограничено 1–32, а параметры GPU принимают только неотрицательное число, `auto` или `all`.

Текущие назначения:

- `ui_butler`: UI-Mate 9B Q4_K_M + projector, официальный backend, 16K, отдельный сервис `ui_fast`, экспериментальный;
- `research_fast`: Agents-A1 4B Q4_K_M, официальный backend, 16K, отдельный сервис `research_fast`, экспериментальный;
- `generalist`: Laguna XS 2.1 APEX I-Quality + DFlash, PoolSide backend, 96K;
- `reasoning`: Qwen 3.8 27B Opus Distill v2 + MTP + projector, официальный backend, 96K;
- `heavy_candidate`: Laguna S 2.1 UD-IQ3_S, PoolSide backend, 96K, `experimental: true`, `enabled: false`;
- `candidate`: conFIGur8tor Ornith 1.5 35B-A3B APEX MTP Fixed, 16K, `experimental: true`, `enabled: false`;
- `quality_candidate`: mudler Ornith 1.5 35B-A3B APEX Quality Q6_K без MTP, 16K, `experimental: true`, `enabled: false`.

У кандидатов хранится лучший измеренный режим запуска, поэтому после A/B у `heavy_candidate`, `candidate` и `quality_candidate` стоит `acceleration: none`. Наличие DFlash/MTP-артефакта не означает, что ускорение полезно. Для воспроизводимого sweep benchmark принимает явные `--acceleration-type` и `--spec-tokens`, изменяя профиль только в памяти процесса. Результаты: `docs/MODEL-RUNTIME-AB-2026-08-30.md`.

Новый GGUF сначала добавляется отдельным выключенным кандидатом. Штатная команда `python scripts\model-assets.py download candidate` загружает все объявленные артефакты только из закреплённых commit и принимает их после совпадения размера и полного SHA-256. `python scripts\model-assets.py verify candidate` не обращается к сети и проверяет уже разрешённые локальные пути. PowerShell-вход `scripts\download-model-assets.ps1 -Profile candidate` использует тот же код и каталог.

Перед первым runtime-запуском полный SHA-256 проверяется ещё раз и записывается в `runtime/models/integrity.json` только вместе с file identity и временными метками. Повторный запуск доверяет записи лишь пока эта сигнатура полностью совпадает; изменившийся файл перечитывается. Символическая ссылка вместо GGUF запрещена.

Конкретные названия и launch flags допустимы только в этой декларативной записи и её тесте-контракте. В `src` и эксплуатационных скриптах запрещены ветвления по семейству, прежние идентификаторы профилей и абсолютные пути машины; это проверяется автоматическим тестом дистрибутива.

PoolSide не притворяется официальной сборкой. Его полный upstream commit, ветка, локальный patch, параметры сборки и SHA-256 девяти runtime-файлов находятся в `engine.lock.json`. Установщик `scripts/install-local-backend.ps1` принимает только явно указанный каталог уже собранного runtime, проверяет lock целиком, переключает каталог стадийно и сохраняет прежнюю версию. Он не скачивает случайный `latest` и не компилирует недоверенный исходный код во время обычного обновления.

## Контекст и память

Размер контекста — верхняя ёмкость, а не цель заполнять её целиком. Рабочие профили объявляют 96K и KV `K=q8_0`, `V=q4_0`, но веса, speculative decoding, projector и буферы всё равно требуют отдельного живого измерения на закреплённом движке. Сжатие начинается до полного окна; RAG передаёт только релевантные фрагменты. `rag.min_vector_similarity` по умолчанию равен `0.3`: ниже него чисто смысловой кандидат отбрасывается, но найденное FTS5 лексическое совпадение остаётся доступным. Допустимы значения от 0 до 1.

Стартовые значения для другого компьютера находятся в `hardware-profiles.json`. Скрипт оборудования только рекомендует профиль и не меняет рабочие настройки автоматически.

## Ограничение подтверждений

`agent.max_steps` ограничивает короткие агентные задачи, а `agent.developer_max_steps` — длинный контур разработки. По умолчанию это 8 и 24 шага соответственно; лимит разработки обязан быть не меньше обычного и не больше 64. `agent.max_tool_calls_total` ограничивает суммарное число tool-вызовов и обязан покрывать developer-бюджет.

`agent.max_directory_list_calls` ограничивает ручной спуск по дереву каталогов; после шести успешных просмотров агент обязан перейти к `search_workspace` и чтению конкретных файлов. Счётчик сбрасывается на границе каждой пользовательской задачи.

Схемы чтения и поиска не исчезают посреди задачи: реальная проверка показала, что динамическая смена доступного набора может привести модель к подмене намерения ближайшим инструментом. `write_workspace_file` имеет неизменяемый create-only контракт и возвращает `existing_file_requires_replace` для любого существующего пути. Исходники меняются через `replace_in_workspace_file`, который требует ровно одно совпадение старого текста.

`agent.max_confirmation_requests` задаёт число самостоятельных вопросов подтверждения внутри одной задачи. Значение по умолчанию — 4, а код всегда ограничивает его диапазоном 1–8. Связанные обратимые действия, покрытые уже выданным разрешением, не создают нового вопроса. Запуск проектных тестов считается исполнением кода и также требует согласия. После достижения предела Ксения сообщает об остановке повторных подтверждений и завершает задачу без новых инструментов.

«Доверенная задача» намеренно не является полем `user.json`: модель или ошибочная настройка не должны включать постоянный full access. Допуск создаётся только интерактивным локальным управлением, живёт в `runtime`, ограничен 30 минутами и одним запросом. Его безопасные границы не настраиваются вниз.

## Исполнение команд разработчика

`developer.execution.backend` по умолчанию равен `disabled`. Файловые инструменты Ксении продолжают работать внутри `workspace`, но `run_project_command` и `run_project_tests` после подтверждения отвечают безопасным отказом, пока не подключена проверенная ОС-песочница. Неизвестное имя backend, повреждённый раздел или неполная настройка также дают отказ до запуска процесса.

`unsafe_host` сохранён только для осознанной локальной диагностики старого поведения. Он активируется лишь вместе с точной строкой `I_ACCEPT_CODE_EXECUTION_AS_WINDOWS_USER` в `developer.execution.unsafe_host_acknowledgement`. Этот режим не ограничивает Python/Node средствами ОС и не считается sandbox; не включайте его ради устранения сообщения об ошибке. «Доверенная задача» не меняет выбранный backend и не может снять эту блокировку.

## Рассуждение и длина ответа

Поддерживаются уровни `off`, `brief`, `normal`, `deep`. Они меняют режим и ограниченный reasoning budget, но не дают модели бесконечно размышлять. Пользовательский предел ответа — 1024, 4096 или 8192 токенов; маршрутизатор отдельно ограничивает план и каждый этап исследования.

Экспериментальные малые профили дополнительно содержат `request_modes`. Это перезапросная политика, а не новая модель: `enable_thinking`, `max_tokens`, `temperature` и `strategy` выбираются декларативно. У `research_fast` режим `deliberate` включает thinking при server budget 256; `runtime_routing.research_request_modes` привязывает FAST/DELIBERATE к этапам query/synthesis/verification для конкретного профиля. У `ui_butler` deliberate использует `cross_review`, поэтому собственный thinking UI-модели остаётся выключен. `runtime_routing.ui_deliberation` задаёт proposer/reviewer, имена режимов, предел одного revision и отдельный output budget reviewer-а. Код не проверяет названия GGUF.

`model_services` разрешает только loopback, уникальные порты и разные относительные state-файлы внутри `runtime_dir`. Текущие 18082/18083 не заменяют основной 18080. `runtime_routing.fast_resident_models` содержит две роли на разных сервисах; `ResidentModelPool` откатывает только процессы, которые сам успел запустить, и не завершает неизвестного владельца порта.

## Устройства голоса

Bluetooth-имя и индекс нестабильны между переподключениями. Конфигурация хранит предпочтение, а аудиомодуль проверяет реальные режимы устройства. Не хардкодьте индекс, полученный на другом компьютере. При отсутствии устройства голосовой агент должен использовать backoff и оставаться управляемым горячей клавишей остановки.

Если `voice.wake_device` пуст и доступен ровно один аудиовход, Ксения может использовать его автоматически. При двух и более входах требуется явный выбор независимо от Windows default: системным default может оказаться Stereo Mix, line input или другое не предназначенное для речи устройство. Ярлык `Ксения — список микрофонов` позволяет ввести уникальную часть имени, фактически открыть и закрыть совпавший endpoint и только после успешного probe атомарно сохранить селектор в личном `config/user.json`; простого наличия имени в PortAudio недостаточно. Дефис только удаляет сохранённый выбор и при нескольких входах снова включает безопасный отказ. Для скриптов доступны `audio-devices --select "часть имени"` и `audio-devices --clear`. Числовой индекс PortAudio намеренно не сохраняется: после переподключения Bluetooth он может измениться. Неизвестный, отсутствующий, неоднозначный или не открывающийся селектор отклоняется без изменения конфигурации и без перехода к другой гарнитуре. Текущая схема и границы будущего единого capture worker описаны в `docs/AUDIO-FULL-DUPLEX-AUDIT.md`.

`voice.confirmation_microphone_handoff_timeout_seconds` задаёт предел передачи микрофона от фонового stop-listener к распознаванию подтверждения; допустимо от 0,5 до 30 секунд, по умолчанию 5. Все флаги безопасности и активности (`active_control_enabled`, `enabled`, `persistent`, `headless` и другие перечисленные флаги) принимают только JSON `true`/`false`: строка `"false"` считается ошибкой конфигурации, а не истинным значением.

## Live v1

`live.enabled` по умолчанию равен `false`. Значение включает только уже реализованный программный слой: Vosk partial transcripts для semantic endpointing, поток итоговых дельт LLM, фразовый TTS, отслеживание завершения playback, раздельные generated/spoken ответы и согласованную остановку. Vosk определяет только длину паузы, а финальную команду распознаёт faster-whisper. Это ещё не проверенный full-duplex и не AEC. Live требует доступную постоянную Silero-очередь; при её отсутствии флаг безопасно отключается на время процесса с голосовым сообщением. SAPI используется обычным режимом, но не является fallback для отслеживаемых Live-фраз.

`live.semantic_endpointing` по умолчанию равен `true`, но действует только вместе с `live.enabled`. Паузы `live.turn_complete_silence_seconds`, `live.turn_ordinary_silence_seconds` и `live.turn_incomplete_silence_seconds` по умолчанию равны 0,45, 0,85 и 2,2 секунды. Загрузчик требует конечные числа и порядок `0 < complete <= ordinary <= incomplete <= 10`; неверный тип или порядок отклоняется до запуска процесса. Если Vosk-partial недоступен уже внутри worker, один запрос безопасно возвращается к прежнему фиксированному `voice.stt_silence_seconds`.

`live.minimum_phrase_chars` и `live.maximum_phrase_chars` задают границы фрагментов синтеза; по умолчанию 24 и 220 символов. При загрузке конфигурации проверяется условие `1 <= minimum <= maximum <= 2000`. `live.playback_timeout_seconds` ограничен диапазоном 30–3600 секунд и по умолчанию равен 600. Повреждённые значения отклоняются до запуска голосового режима.

До живого теста акустического эха, Bluetooth и команды остановки этот флаг нельзя переносить в `user.json` как обычную настройку. Приёмка должна подтвердить, что Ксения не реагирует на собственный TTS, завершённая фраза учитывается ровно один раз, а прерывание не оставляет очередь или ложную память.

## Секреты

PIN LAN и ключи локального API создаются в `runtime`, не в `default.json`. Пароли сайтов вводятся Александром вручную в отдельном профиле браузера. В конфигурации нельзя хранить токены в URL, командной строке или документации.

## Проверка изменений

После ручного изменения JSON:

1. проверить синтаксис через `AUDIT.cmd`;
2. убедиться, что Doctor показывает фактические пути;
3. перезапустить только затронутую службу;
4. проверить журнал и живой сценарий;
5. не считать отсутствие исключения доказательством правильного GPU-offload или качества модели.
