# Модель угроз и защитные границы

## Доверенные и недоверенные стороны

Доверенными считаются локальный код релиза после проверки, lock-файлы, подтверждённые действия Александра и файлы внутри разрешённого `workspace`. Недоверенными считаются содержимое веб-страниц, поисковая выдача, ответы модели, tool arguments, имена/ссылки из интернета и состояние неизвестного процесса.

LLM никогда не является субъектом разрешения: она предлагает действие, а исполнитель проверяет политику независимо.

## Сетевые границы

- LLM и embeddings привязаны только к loopback и защищены локальным ключом.
- LAN-панель — отдельный HTTP-сервис для доверенной домашней сети с PIN, сессией и rate limit.
- LAN нельзя публиковать в интернет; TLS пока отсутствует.
- Browser worker запрещает `file://`, localhost, приватные/link-local IP, `.local` и URL с учётными данными.
- Редирект проверяется до нового соединения.
- После локального чтения внешний запрос требует подтверждения как потенциальный канал утечки.

## Процессы

- Перед остановкой проверяются PID, полный executable и ожидаемая командная строка.
- Неизвестный владелец порта не завершается.
- Запуск модели имеет bounded timeout; остановка ждёт закрытия process handle и порта.
- Дочерние browser/STT/UIA процессы имеют тайм-ауты и ограниченный протокол stdin/stdout.
- Agent command runner не использует shell, inline-код и не принимает произвольный PowerShell/cmd.

## Файлы и секреты

- Обычные операции ограничены `workspace` после окончательного разрешения пути.
- Симлинк/relative traversal не должен выводить наружу.
- `.env`, credentials, private keys, сертификаты, password databases и похожие имена/расширения запрещены до чтения.
- Секретные файлы не попадают в поиск и RAG.
- Изменение имеет резервную копию и hash; отмена не затирает последующую ручную правку.
- Дистрибутив исключает личную конфигурацию, runtime, workspace, модели и ключи.

## Подтверждения

- Безопасное чтение обычно разрешено.
- Запись, удаление, команды, UI, клавиатура, мышь и активный браузер подтверждаются.
- Удаление и отправка сообщения подтверждаются отдельно каждый раз.
- Покупка, оплата и перевод запрещены.
- Проверка финансового контекста применяется и к общим средствам ввода.

Нельзя ослаблять подтверждение потому, что «модель уверена» или задача сформулирована голосом.

## Диагностика и приватность

Журнал хранит тип события, компонент, длительность, размеры и безопасные исходы. Он не должен хранить полный запрос/ответ, вводимый текст, содержимое файла, PIN, пароль, API key, параметры URL или полную команду. Новое поле диагностики проходит `safe_value` и отдельный тест утечки.

## Supply chain

- Python installer проверяется Authenticode и издатель.
- Архивы `llama.cpp`, Vosk и известные веса speech pack проверяются SHA-256.
- Python-версии фиксируются lock-файлами.
- Новая upstream-версия сначала считается кандидатом, а не автоматическим обновлением.
- Release archive получает собственный список SHA-256 и машинную проверку запрещённых файлов.

Оставшийся риск: зависимости Python пока фиксируются точными версиями, но без hash каждого wheel. Для полностью автономного офлайн-релиза потребуется собственный подписанный wheelhouse с хешами и отдельная проверка лицензий.

## Реакция на подозрительное поведение

1. Остановить голос `Control + Alt + S`.
2. Не завершать неизвестный процесс по одному номеру порта.
3. Сохранить время и безопасные журналы.
4. Отключить сеть, если есть риск внешнего действия.
5. Запустить аудит из доверенного дерева.
6. Сравнить бинарники/архивы с lock-файлами.
7. Не очищать доказательства до диагностики.
