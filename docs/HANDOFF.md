# Передача проекта человеку или другой нейросети

## Назначение

Этот документ позволяет принять проект без доступа к прежней переписке. Основной пользователь — Александр, слабовидящий и не программист. Рабочий результат для него — понятный ярлык, русский голос, своевременный статус и безопасное подтверждение, а не команда в терминале.

## Быстрое принятие проекта

1. Прочитайте `AGENTS.md`, `README.md` и `docs/AUDIT.md`.
2. Не запускайте `INSTALL.cmd` на уже настроенном компьютере только ради проверки.
3. Откройте `config/user.json` только для понимания путей; не публикуйте и не заменяйте его.
4. Проверьте `runtime/state.json`, фактический PID и командную строку процесса модели.
5. Прочитайте конец `runtime/audit/latest.txt` и последние безопасные события `runtime/logs/diagnostics.jsonl`.
6. Запустите `AUDIT.cmd`, если состояние компьютера позволяет выполнить тяжёлые проверки.
7. Сверьте незакрытые пункты в `docs/ROADMAP.md`.

## Что реализовано

- Четыре функциональные роли: ассистент, исследователь, разработчик и тяжёлый мозг.
- Один активный `llama-server` с безопасной сменой GGUF-профиля.
- Контекст до 64K, асимметричный KV, MTP для подходящих моделей, управляемые reasoning и длина ответа.
- Голос: Vosk для активации/остановки, faster-whisper для команды, Silero Xenia и SAPI-резерв.
- Память разговора, подтверждённые факты, межролевая передача и гибридный RAG с порогом уверенности и явным `no_match`.
- Исследование через поиск, изолированный Chromium, стабильный порядок доказательств, приоритет официальных источников и проверку цен.
- Ограниченная разработка в `workspace`, Windows Automation, клавиатура, мышь и браузер с неослабляемой политикой и пределом вопросов подтверждения.
- Локальная одноразовая «Доверенная задача»: один предварительно согласованный запрос без повторных вопросов, с 30-минутным сроком до начала, атомарным потреблением и неизменными hard deny.
- LAN-панель с PIN и доступностью с клавиатуры/screen reader.
- Долговечные задачи, пауза, отмена, восстановление и безопасные журналы.

Фактически проверенное состояние находится в `docs/AUDIT.md`; не копируйте цифры из этого документа в новый отчёт без повторного измерения.

## Основной поток

```text
микрофон / горячая клавиша / JBL / LAN
             → wake/STT
             → долговечная задача
             → маршрутизатор роли
             → одна локальная LLM
             → инструменты и подтверждения
             → память/RAG/проверка
             → экран и TTS
```

Функциональная роль описывает задачу. Профиль модели описывает конкретный GGUF и аргументы `llama.cpp`. Не связывайте эти понятия жёстко: модель можно заменить, не переписывая инструменты роли.

## Постоянные данные

| Данные | Путь | Правило |
|---|---|---|
| Личные настройки | `config/user.json` | Сохранять при обновлении, не включать в архив |
| Текущий процесс LLM | `runtime/state.json` | Доверять только после проверки PID и exe |
| Диалог и сводка | `runtime/memory/session.json` | Пользовательские данные |
| Факты | `runtime/memory/knowledge.sqlite3` | Только подтверждённые Александром |
| Межролевая память | `runtime/memory/handoffs.sqlite3` | Задача, план, ошибки и итог |
| RAG | `runtime/rag/rag.sqlite3` | Восстанавливаемый индекс; источники в `workspace` |
| Задачи | `runtime/tasks` | Нельзя стирать при обновлении |
| Ожидающий допуск | `runtime/permissions/trusted-next-task.json` | Не переносить; при сомнении отменить локальным ярлыком |
| Журналы | `runtime/logs` | Безопасная метаинформация, ротируется |
| Отчёты | `runtime/audit`, `runtime/benchmarks` | Доказательства конкретного прогона |

## Где менять поведение

- Роль и маршрутизация: `orchestrator.py`, `research.py`, `agent.py`.
- Жизненный цикл моделей: `model_manager.py`, `embeddings.py`, `chat.py`.
- Разрешения и действия: `permissions.py`, `approval.py`, `confirmation.py`, `trusted_task.py`, `tools.py`, `browser.py`.
- Голос: `wake.py`, `stt.py`, `speech.py`, `speech_text.py` и дочерние скрипты.
- Память: `memory.py`, `knowledge.py`, `handoff.py`, `rag.py`, `tasking.py`.
- Интерфейсы: `cli.py`, `lan.py`, `web`, командные файлы и ярлыки.
- Установка/обновление: lock-файлы, `install-*.ps1`, `update.ps1`, `build-release.ps1`.

Полная таблица модулей: `docs/SOURCE-MAP.md`.

## Текущие пользовательские границы

Программно можно проверить почти весь контур. Александр принимает физическую часть: микрофон и динамик JBL, пять wake-активаций, голосовую остановку, сенсорный жест, телефон в LAN и реальные внешние сайты. Координатные клики и отправка сообщений не должны выполняться автоматически ради теста.

## Диагностика без догадок

1. Зафиксировать примерное время и интерфейс запуска.
2. Посмотреть `runtime/logs/diagnostics.jsonl` и журнал конкретного процесса.
3. Проверить владельца порта и фактическую командную строку.
4. Воспроизвести минимально безопасным сценарием.
5. Добавить регрессионный тест, который краснеет до исправления.
6. После исправления выполнить связанный live-gate и полный аудит.

Не просите Александра пересказывать техническую ошибку по памяти, если журнал может дать точный ответ.

## Перед завершением своей смены

- Запишите, что изменено, что измерено и что не удалось проверить.
- Обновите документацию и тесты в том же изменении.
- Оставьте рабочую модель и голосовой режим в известном состоянии.
- Убедитесь, что порты тестовых LAN/RAG/моделей освобождены.
- Не оставляйте повреждённые загрузки среди рабочих моделей.
- Не объявляйте задачу законченной только потому, что unit-тесты зелёные.
