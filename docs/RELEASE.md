# Сборка переносимого архива

## Назначение

`BUILD-RELEASE.cmd` создаёт чистый online-архив, который можно распаковать на другой Windows-компьютер и запустить через `INSTALL.cmd`. Архив не является резервной копией личных данных Александра.

## Перед сборкой

1. Обновить версию и дату в `pyproject.toml` и `config/release-manifest.json`.
2. Сверить lock-файлы и документацию.
3. Выполнить `AUDIT.cmd`.
4. Убедиться, что Git-дерево чистое и в source tree нет случайных весов, ключей или выгрузок пользователя.
5. Запустить `BUILD-RELEASE.cmd`.

## Что делает сборщик

1. По умолчанию прекращает сборку, если Git-дерево содержит staged, unstaged или untracked изменения; диагностический `-AllowDirtySource` не разрешён для выпуска.
2. Читает только разрешённые корни/файлы из `release-manifest.json`.
3. Отклоняет запрещённые расширения и личные пути.
4. Копирует файлы в случайный staging внутри выбранной папки выпуска.
5. Создаёт `PACKAGE-MANIFEST.json` с размером и SHA-256 каждого файла.
6. Запускает `validate_release.py` по staged tree.
7. Создаёт `dist/Ksenia-<version>-online.zip`.
8. Распаковывает архив в новый временный каталог и повторно проверяет состав и хеши.
9. Удаляет только проверенные временные каталоги.

## В архив входит

- код, тесты и процедуры;
- документация человека/ИИ;
- lock-файлы и конфигурация по умолчанию;
- иконки и web-интерфейс;
- CMD/PowerShell/Python installer, updater, rollback и audit;
- пустая стартовая рабочая инструкция `workspace/README.txt`.

## В архив не входит

- `config/user.json`;
- весь `runtime`;
- пользовательские файлы `workspace`;
- `.git`, `.venv`, временные вложения и кэши;
- распакованный `llama.cpp` и скачанные архивы;
- GGUF, safetensors, PT/PTH, ONNX, CKPT, TFLite, NeMo, Whisper/embedding/TTS weights;
- ключи, сертификаты, password databases и browser profile.

Если запрещённый файл найден, сборка завершается ошибкой, а не молча исключает неоднозначный путь.

## Проверка получателем

После распаковки можно проверить дерево до установки:

```powershell
py -3.12 scripts\validate_release.py --package-root .
```

После `INSTALL.cmd` выполняется полный `AUDIT.cmd`. `PACKAGE-MANIFEST.json` доказывает целостность архива, но не доказывает совместимость конкретной LLM или физического микрофона.

## Offline-вариант

Текущий канонический релиз — online bootstrap. Полный offline-набор потребует проверенного wheelhouse, установщика Python, Chromium, архивов движка и отдельных model packs; его размер будет несколько гигабайт даже без LLM. Нельзя называть архив офлайн-полным, пока каждый бинарный файл не закреплён хешем и не прошёл установку в чистой Windows VM.

## Публикация на GitHub

Публичный репозиторий не является резервной копией рабочего компьютера. Перед push обязательно:

1. выполнить полный gate и `BUILD-RELEASE.cmd`;
2. проверить `git status --ignored` и состав индекса через `git diff --cached --name-only`;
3. убедиться, что `.codex-remote-attachments`, `config/user.json`, `runtime`, `workspace` пользователя, `dist`, модели и браузерный профиль не отслеживаются;
4. проверить staged-дерево отдельным поиском секретов и расширений весов;
5. создать подписанный по смыслу tag вида `v<version>-alpha.<n>`;
6. публиковать ZIP только как GitHub prerelease asset, не добавляя его в Git;
7. указать SHA-256 ZIP, ограничения alpha и необходимость отдельных моделей в release notes.

После публикации проверяются страница README, эмблема, Windows Actions, доступность release asset и приватный канал Security Advisory.
