# Задание 2 для Fable 5.1: аудит нового кода + веб-приложение (PWA) для планшета

Репозиторий: Alexperowo/assistant-ksenia, ветка `main`. Работай в **отдельной ветке**, итог — **pull request**.
Сначала прочитай README.md, ROADMAP.md (особенно «Принципы»), docs/REVIEW.md (твоё прошлое ревью — оно принято
и внедрено), затем код. Пиши по-русски.

Главный ориентир проекта: **Ксения — живой голосовой ассистент** для Александра (инвалидность первой группы по зрению).
Не программист и не чат-бот: быстро, по-человечески, сама действует, всё понятно на слух.

## Ограничения (как в прошлый раз)
- В облаке нет железа (2 GPU, Bluetooth, KDE/Wayland, модели). Не запускай сервисы и не качай модели.
- Не меняй без веской причины (и с пометкой в отчёте): историю «только дописывать» (мозг Nex — гибридная модель);
  логику Bluetooth HFP/A2DP в voice-in; распределение по видеокартам и порты; `persona.md` (правки — списком).
- Подтверждение рискованных действий выполняет ЯДРО (`core/tools/confirm.py` + `is_affirmative`), не модель.
  Это нельзя ослаблять.
- Секретов в коде нет и не должно быть (`secrets/`, `brain/api_key`, `data/` — вне git).

## Часть 1. Аудит нового кода (после твоего прошлого ревью)
Новые модули: `core/tools/vk.py`, `web.py`, `browser_core.py`, `desktop.py` + `atspi_helper.py`, `memory.py`,
`research.py`, `daily.py`, `confirm.py`, изменения в `core/core.py` (подтверждения, фоновые находки, напоминания,
окно истории по объёму, повтор после ServerDisconnected, вырезание `<think>`).
Особое внимание:
- **подтверждения:** можно ли обойти ядро (модель, текст со страницы, превью сообщений ВК, название станции);
  гонки (подтверждение пришло, пока идёт другое действие); устаревание;
- **prompt injection** из недоверенных источников (страницы, ВК, буфер обмена, OCR, результаты поиска);
- **web.py:** проверка публичных адресов (SSRF, DNS rebinding между проверкой и `goto`, редиректы на локальные адреса);
- **desktop.py / atspi_helper.py:** что будет на зависшем приложении, огромном дереве, нечитаемых именах;
- **research.py / фоновые циклы:** утечки задач, двойная доставка находок, поведение при перезапуске;
- **daily.py:** часовые пояса, «в 7:00» после 7:00, повреждённый файл, напоминание во время разговора.
Тесты (pytest, без сети и железа) — на всё новое. Находки — в `docs/REVIEW-2.md` по убыванию важности.

## Часть 2. Веб-приложение Ксении для планшета (PWA)
Александр говорит с Ксенией через планшет Galaxy Tab S9 Ultra (Android, Chrome) в домашней сети: вместо Bluetooth-
наушников у ПК или вместе с ними. Сейчас ядро и слух принимают запросы только с этого компьютера (`local_only`) —
так и оставить. Нужен **отдельный модуль-шлюз** `pwa/` со своим сервисом systemd `ksenia-pwa`.

Возьми полезное из старой Windows-версии (ветка `windows-legacy`): `web/index.html`, `web/sw.js`,
`web/manifest.webmanifest`, иконки `web/icon-*.png`, `src/butler/lan.py` (PIN, сессия, ограничение частоты),
`scripts/gateway.mjs` (там был HTTPS). Не копируй вслепую — там был Windows и другой бэкенд.

Требования:
1. **Шлюз** (Python, aiohttp, как остальной код): HTTPS в домашней сети; самоподписанный корневой сертификат
   генерируется скриптом один раз (+ понятная инструкция, как установить его на Android); PIN при первом входе,
   затем долгая HttpOnly-сессия; ограничение попыток PIN; проверка Origin; доступ только из локальной сети;
   к ядру и слуху ходит сам по 127.0.0.1 (их `local_only` не трогать).
2. **Говорить:** крупная кнопка «Говорить» (нажал — говоришь — отпустил, и вариант «нажал — говорит до паузы»),
   запись в браузере (MediaRecorder) → шлюз → `voice-in /transcribe` (уже есть) → реплика в ядро.
3. **Слышать ответ на планшете:** ответ Ксении должен звучать на планшете (её голос, не синтез браузера).
   Сейчас ядро играет звук только локально (`Speaker` → `pacat`). Нужна аккуратная абстракция вывода в ядре:
   у реплики есть «куда говорить» — локально (как сейчас) или клиенту (поток PCM/Opus/MP3 через WebSocket или
   chunked HTTP). Локальный путь должен работать как прежде. Перебивание (новая реплика/стоп) прерывает звук на планшете.
4. **Подтверждения:** когда Ксения спрашивает «Отправить?», на экране — две крупные кнопки «Да» / «Нет»
   (отправляют реплику «да»/«нет» в обычный поток — решение по-прежнему принимает ядро).
5. **Текст разговора:** реплики крупным шрифтом, последняя сверху или внизу — продумай для слабовидящего.
6. **Доступность:** всё доступно экранному диктору TalkBack (aria), крупные цели касания, высокий контраст,
   тёмная тема, вибрация на «слушаю/думаю/говорю», экран не гаснет во время разговора (Wake Lock).
7. **Состояния:** «слушаю», «думаю», «говорю», «нет связи с компьютером» — и голосовой/вибро-сигнал, не только цвет.
8. Музыку на ПК при разговоре с планшета приглушать так же, как сейчас (`music.duck`).
9. Тесты шлюза (PIN, сессия, Origin, ограничение частоты, проксирование) без сети и железа.

проверить вживую на планшете по шагам).
