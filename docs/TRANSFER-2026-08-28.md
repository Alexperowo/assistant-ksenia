## 3. Live: точный статус

### Реализовано и проверено программно

- отдельные `LiveSession`, `StreamingTTS`, `BargeInController`, `ConversationCoordinator`;
- потоковая разбивка безопасного итогового текста на законченные фразы;
- cancellation event выставляется до остановки аудио;
- поздние и переставленные callbacks не добавляют отменённую речь;
- `generated_answer` и `spoken_answer` разделены;
- в память попадает только непрерывный префикс полностью завершённых фраз;
- Vosk partial transcripts участвуют в hybrid endpointing, финальную команду формирует faster-whisper;
- микрофонный stop-listener явно передаёт устройство голосовому подтверждению;
- Silero worker имеет ready/error handshake и не подменяется поздним дублирующим SAPI.

### Не реализовано и не принято

- WebRTC AEC3 или другой проверенный acoustic echo cancellation;
- постоянный full-duplex near/far audio engine;
- живой произвольный речевой barge-in рядом с динамиками;
- проверка на текущих JBL, реальном помещении и разных уровнях громкости;
- гарантия, что TTS Ксении не будет принят микрофоном за речь Александра.

Поэтому эффективное значение остаётся `live.enabled: false`. Его нельзя молча включать в `config/user.json`. Ярлык «НАЧАТЬ РАЗГОВОР» сейчас запускает проверенный обычный voice-agent, а не принятый full-duplex Live.

### Следующий безопасный Live-gate

1. Выбрать AEC-кандидата только после фиксации версии, источника и SHA-256 бинарного артефакта.
2. Прогнать synthetic near+far: far-end TTS не должен появляться в очищенном near-end потоке, голос пользователя должен сохраняться.
3. Добавить один постоянный audio engine с общей временной шкалой mic/render reference.
4. Проверить barge-in сначала в наушниках, затем через динамики на нескольких уровнях громкости.
5. Подтвердить порядок: speech detected → LLM cancel → TTS queue cancel → playback stop → listening.
6. Проверить, что после перебивания память содержит только реально услышанный текст.
7. Только после серии живых успешных прогонов обсуждать включение Live по умолчанию.

## 7. Неослабляемые границы

- Permission Broker решает право действия независимо от LLM.
- Tool arguments проходят строгую схему до политики и executor.
- Активное управление браузером и Windows по умолчанию выключено.
- Неизвестный active/target window приводит к fail-closed отказу ввода.
- Командный backend остаётся `disabled`, пока нет production Sandbox Worker. `unsafe_host` не является sandbox.
- Покупки, платежи и переводы запрещены.
- Веб-страница, модель и голосовая команда не могут включить «Доверенную задачу».
- GGUF проверяется по размеру и полному SHA-256 перед первым runtime-запуском; cache доверяется только неизменной file identity.
- Файловые изменения и undo-record сериализованы; симлинки целей и backup отклоняются.
- Release нельзя собирать из грязного Git-дерева; `-AllowDirtySource` не предназначен для выпуска.
