# Ксения для Linux — анализ Windows-версии

Дата: 2026-10-06. Источник: `/media/SATA1/Project/assistant-ksenia`
(совпадает с GitHub `Alexperowo/assistant-ksenia`, коммит 5202791 от 21.09.2026).
SATA1 не меняем, только читаем.

## Философия новой Ксении (слова Александра, 2026-10-06)

Ксения — не разработчик и не OpenHands. Она живой напарник и помощник:
- напишет за тебя сообщение во ВКонтакте через браузер;
- включит музыку, которую попросишь, или предложит сама;
- развлечёт: разговор, истории, игры;
- поможет неопытному пользователю Linux;
- сама откроет, сама нажмёт, доведёт дело до конца.

**Характер обязателен.** Ксения — живая личность с эмоциями, может быть и дерзкой:
шутит, подкалывает, радуется, ворчит, имеет своё мнение и предлагает сама.
Не безликий вежливый бот. Характер задаётся в промпте и проверяется на слух
(эмоции должны звучать и в тексте, и в голосе).

От старой Ксении берём фундамент, а не роль разработчика.
Цель — Fedora 45 KDE (скоро переход), поэтому всё делаем независимым от дистрибутива:
systemd user-сервисы, PipeWire, KDE Plasma Wayland, Flatpak/PackageKit вместо apt.

## Что такое старая Ксения

Локальный русский голосовой ассистент для Windows: дворецкий, исследователь, разработчик.
Python 3.12, ~26 тыс. строк в `src/butler`, 592 теста, 14 ГБ на диске
(в основном бинарники llama.cpp, runtime и загрузки).

Цепочка: Vosk «Ксения слушай» → faster-whisper (CUDA) → оркестратор ролей →
llama-server (3 модели: Qwen 27B, UI-Mate 9B, Agent A1 4B) → инструменты с
подтверждениями → память SQLite → Silero Xenia → динамики или наушники.

## Берём (логика переносится почти без изменений)

1. **Принципы и характер.** Напарница от женского лица, короткие голосовые статусы,
   рассуждения модели не озвучиваются, всё понятно на слух. Правила COMPLETE и PRISM
   из `AGENTS.md` для разработки.
2. **Голосовой контур — архитектура.** Wake-слово Vosk Small RU → faster-whisper
   Large v3 Turbo (на Linux работает так же) → TTS. Кусочки без привязки к ОС:
   - `speech_text.py` — числа, даты и время словами, таблица ударений («гот+ов»);
   - `turn_detection.py` — определение конца реплики по паузе и смыслу;
   - `live.py` — потоковая озвучка, перебивание, разделение «сгенерировано» и «сказано».
3. **Безопасность.** `permissions.py`, `approval.py`, `confirmation.py`:
   разрешить, спросить, запретить; минимум защиты нельзя ослабить настройкой;
   не больше 4 вопросов на задачу; запрет финансов; «Доверенная задача» на один запрос;
   `journal.py` — резервная копия и отмена изменений файлов; `sensitive_data.py`.
4. **Память слоями.** История со сжатием, `knowledge.py` (подтверждённые факты),
   `handoff.py` (передача задачи между ролями), `rag.py` (FTS5 + векторы + RRF,
   честный ответ «ничего не найдено»), Qwen3-Embedding 0.6B на CPU.
5. **Интернет.** `research.py` и `browser.py`: DuckDuckGo, Bing RSS, Google News RSS,
   защита от локальных адресов, общий лимит времени. `weather.py` — погода без LLM.
   `fast_intents.py` — мгновенные ответы без модели.
6. **Надёжность.** `tasking.py` (задача на диске, пауза, отмена, восстановление),
   `diagnostics.py` и `performance.py` (журнал с trace_id без текста разговора),
   отмена HTTP-потока за ~0,5 с (`chat.py`).
7. **Модели как данные.** Профили моделей и движков в конфиге, без условий по имени
   модели в коде (решения D-017, D-018). Подходит для ik_llama-fresh и llama.cpp-mainline.
8. **Процедуры** (`procedures/*.json`) — по сути навыки: разработка, сообщения,
   исследование товаров, установка программ, управление компьютером.

## Поправки после уточнения философии

- Роль «разработчик», RAG по коду, запуск тестов — убираем из ядра.
- Главное становится: управление компьютером (экран + клики), браузер со своим
  профилем и входом во ВК, музыка (поиск, очередь, MPRIS), разговор и развлечения,
  помощь новичку в Linux (объяснить и сделать за него, с подтверждением).
- Из старой Ксении особенно ценны: подтверждения перед отправкой сообщений
  и удалением, процедура `messages.json`, `browser.py`, голосовой контур, память фактов.
- При переходе на Fedora движки llama (CUDA) придётся пересобрать; модели переносятся как есть.

## Решено

1. Ксения — самостоятельный ассистент на фундаменте старой Ксении, не надстройка над Antigravity.

2. Модель: быстрая (живой диалог), но не глупая (будет выполнять команды и в терминале).
3. Голос: нужен высший уровень — качественный женский голос с эмоциями (искать новое).
4. Общение: микрофонов у ПК нет. Двое Bluetooth-наушников + планшет — оба канала.

## Модель: черновик

Для живого диалога важно время до первой фразы, а не только скорость.
Размышления (thinking) — главный тормоз: Tinfield тратит ~30 с на шаг.
Кандидат — Nex-N2.5-mini IQ4_XS на RTX 5060 Ti (измерено: генерация 63 т/с,
промпт 444 т/с при 32K, зрение в VRAM). Тогда RTX 2080 Ti свободна под голос
(TTS + Whisper). Русский у Nex ещё не проверен — проверить в первую очередь.

## Звук: важное ограничение Bluetooth

Если микрофон наушников открыт постоянно (wake-слово), наушники переходят
в режим гарнитуры (HFP): музыка и голос Ксении становятся глухими.
Варианты: активация кнопкой наушников (было в старой Ксении — media_buttons),
микрофон только на время реплики; планшет — отдельный канал (PWA или приложение).

## Основа управления: предложение (2026-10-07, ждёт решения)

Своё ядро, а не чужая платформа. Старая Ксения тоже была на своём ядре
(`agent.py` + `orchestrator.py` + `tools.py`). Берём её идеи, но пишем заново и компактно:
цикл вызова инструментов к llama-server (OpenAI API), динамический бюджет
рассуждений, подтверждения голосом, память, характер.

Инструменты — отдельными MCP-серверами: их можно проверять по одному
и брать готовые (например, Playwright MCP для браузера).

Голосовой слой — кандидат Pipecat (открытый, Python): потоковый STT→LLM→TTS,
перебивание, определение конца реплики, передача звука с планшета через WebRTC.
Проверить перед выбором.

Нужные инструменты Linux/KDE:
- экран: снимок KWin/spectacle → Nex смотрит и даёт координаты;
- точные клики без зрения: дерево доступности AT-SPI;
- мышь и клавиатура: ydotool или портал RemoteDesktop (Wayland);
- окна: KWin-скрипты через D-Bus;
- браузер: Playwright со своим профилем (вход во ВК сохраняется);
- музыка: mpv + yt-dlp, playerctl (MPRIS), громкость wpctl;
- программы: запуск, установка через PackageKit/Flatpak с подтверждением;
- напоминания: systemd-таймеры, уведомления;
- терминал: только в песочнице bubblewrap и с подтверждением;
- планшет: своя PWA Ксении (решено 2026-10-07), не KDE Connect.

## Fish S2 Pro: первые замеры (2026-10-07)

s2.cpp, q8_0, все 36 слоёв на GPU, кодек на GPU, без образца голоса.
- RTX 2080 Ti: ~5,8 ГБ VRAM; 12 потоков CPU — 64 мс на кадр (RTF 1,4, медленнее реального времени);
  4–6 потоков — 44 мс на кадр (RTF ~0,94, впритык).
- RTX 5060 Ti: ~69 мс на кадр (12 потоков) — не быстрее.
- GPU загружена ~40%: упор в CPU и накладные расходы (Fast-AR, 10 мелких шагов на кадр).
  По пропускной способности памяти теоретический предел ~15–20 мс на кадр → есть запас в 2–3 раза
  (CUDA graphs, официальный fish-speech с torch.compile).
- Без образца голос случайный (высота 175–240 Гц, женский диапазон). Нужен образец голоса.
Запуск: `CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=1 s2 -m ... --cuda 0 -ngl 99 -threads 4`.

## Принцип: модульность (требование Александра)

Каждая часть — отдельный модуль со своим сервисом systemd, своим конфигом и простым
интерфейсом (HTTP/WebSocket на localhost). Модуль можно перезапустить, заменить или
проверить отдельно, не трогая остальные:
- `brain` — llama-server с Nex (уже есть основа);
- `voice-out` — синтез речи (S2 Pro; движок меняется без правки остальных модулей);
- `voice-in` — распознавание речи (Whisper) и определение конца реплики;
- `core` — ядро Ксении: диалог, характер, бюджет рассуждений, подтверждения, память;
- `tools` — инструменты отдельными MCP-серверами (экран, браузер, музыка, система…);
- `pwa` — веб-приложение для планшета (HTTPS, звук потоком).

**Решено 2026-10-07:** голос Ксении — Маша (`voice-tests/voices/masha.s2voice`, образец `ref_masha.wav`).

## Официальный fish-speech: замер (2026-10-07, RTX 2080 Ti, fp16 --half, образец Маши)

| Движок | мс на кадр (46 мс звука) | RTF | VRAM |
|---|---|---|---|
| официальный, без compile | 77 | 1,66 | 15,3 ГБ |
| официальный, torch.compile | 36 | 0,79 | 15,5 ГБ (сборка при старте ~3,5 мин) |
| s2.cpp q8, образец Маши | 58 | 1,25 | ~6 ГБ (поток) |
| s2.cpp q8, без образца | 44 | 0,94 | ~6 ГБ |

Вывод: склейка шагов (CUDA graphs в torch.compile) даёт ×1,6 — гипотеза про накладные
расходы подтвердилась. Но официальный берёт 15,5 ГБ — ломает запас 10–12 ГБ на 2080 Ti.
Путь: ускорять s2.cpp (CUDA graphs / меньше синхронизаций CPU↔GPU в Fast-AR).
Обход падения torchaudio (sox SIGSEGV): обёртка с backend="soundfile".
Официальный движок и его модель удалены 2026-10-07 (освобождено ~19 ГБ). Остались только коды теста в voice-tests/official (2 МБ).

## Ускорение s2.cpp (ветка `ksenia-perf` в ~/backend/s2.cpp, 2026-10-07)

Замеры: голос Маши, q8_0, RTX 2080 Ti, 4 потока. Один кадр = 46 мс звука.
| Шаг | Fast-AR | Slow-AR | RTF |
|---|---|---|---|
| исходно | 16,5 мс | 36,5 мс | 1,25 |
| эмбеддинги и выходная голова на GPU (были на CPU из-за осторожности автора для K-quant) | 16,4 | 25,6 | 1,02 |
| CUDA graphs (GGML_CUDA_GRAPHS=ON) | без изменений | | |
| Flash Attention по F16 KV-кэшу для шага декодирования (вместо concat+repeat+cast) | 16,1 | 12,7 | 0,73 |
Откат без пересборки: `S2_CUDA_EMBD_CPU=1`, `S2_NO_FA=1`.
Дальше: Fast-AR (9 вызовов на кадр, граф собирается заново, префикс пересчитывается без KV).
| KV-кэш + Flash Attention для Fast-AR (10 вызовов по 1 токену вместо пересчёта префикса) | 12,4 | 12,6 | ~0,6 |
Проверка точности `S2_VERIFY=1` (сравнение с исходным путём на тех же данных):
KL распределений в среднем 0,0002, максимум 0,0007 — на слух неотличимо. Откат Fast-AR: `S2_FAST_NO_KV=1`.
Длинная запись 31 с с 8 эмоциями (`ksenia-masha-emotions.mp3`): пик VRAM 9,0 ГБ (поток, длинный текст);
с Whisper (~1,5 ГБ) свободно ~12 ГБ — на границе запаса Александра.

## Потоковая озвучка (сервис voice-out, 2026-10-07)

- Кодеку нужна история 144 кадра (оконный трансформер 128): урезание окна портит звук (SNR 7–11 дБ к эталону).
- Свёртки декодера причинные: holdback 0 точен (47 дБ). Тяжёлую часть (апсемплинг+декодер) считаем
  только по новым кадрам + 8 разгона (`S2_CODEC_TAIL=8`, 46,8 дБ).
- `conv_transpose_1d` переписан через GEMM (cuBLAS) + сложение со сдвигом (48,3 дБ), полный декод ×2 быстрее.
- Кэш собранных графов кодека по размеру окна (LRU 16), отдельный поток декодера.
Итог на длинной фразе (9–10 с звука): первый звук 0,6–0,85 с, RTF 0,68–0,70.
Параметры запроса: stream+chunked, pcm_s16le, stream_holdback_frames 0, stream_decode_stride_frames 8.
Сервер после ответа ещё ~1 с занят (503 busy) — ядро должно ставить фразы в очередь с повтором.
